# juntarpdf.com

Free PDF tools for the Portuguese-speaking market, built as a static site where
**every file is processed inside the visitor's browser**. Nothing is uploaded,
so there is no per-operation server cost — and no limits, no sign-up and no
watermarks to enforce.

```bash
npm install
npm run build      # -> dist/
npm run dev        # build + preview on http://localhost:4173
npm test           # build + structural checks + real browser tests
```

## Why local processing is the whole strategy

Every competitor in this niche (iLovePDF, Smallpdf, PDF24, juntarpdf.net) sends
the document to a server. That forces them into the same business model: three
files a day, sign up for the fourth, subscribe to remove the watermark.

Doing the work in the browser removes the cost per operation, which removes the
reason for those limits. It is also the honest answer to the question every
person with a contract or a medical report is quietly asking: *where does my
file go?* Here, nowhere. `npm test` asserts this — the suite fails if any
request leaves the page carrying a payload.

## Repository layout

```
src/
  data/
    site.mjs          brand, navigation, trust badges
    tools/            17 tool definitions (copy, FAQ, HowTo, options)
    guides/           8 long-form guide pages
    static-pages.mjs  about, privacy, terms, contact
  templates/
    layout.mjs        <head>, schema.org @graph, header, footer
    pages.mjs         page bodies
    widgets.mjs       per-engine tool controls
    icons.mjs         inline SVG set
  assets/
    css/main.css      design system, inlined into every page at build time
    js/core.js        drop zone, file list, ZIP writer, lazy library loading
    js/tool.js        the 15 PDF engines
  build.mjs           generates dist/
scripts/
  check.mjs           titles, descriptions, H1s, canonicals, links, JSON-LD
  e2e.mjs             drives every tool in Chromium and inspects the output
  images.mjs          favicon, PWA icons, per-page Open Graph cards
public/               static passthrough (icons, og cards)
```

Adding a tool means adding one object to `src/data/tools/*.mjs` and one engine
to `src/assets/js/tool.js`. Pages, navigation, the sitemap, internal links and
all structured data follow automatically.

## The tools

All 15 engines run client-side and are covered by `scripts/e2e.mjs`.

| Tool | Engine | Implementation |
| --- | --- | --- |
| Juntar, Dividir, Extrair, Remover, Organizar, Girar | pdf-lib | pages copied without recompression |
| Numerar páginas, Marca d'água, Assinar | pdf-lib | drawn with standard fonts / embedded PNG |
| Comprimir | pdf.js + pdf-lib | re-render at a chosen DPI, re-embed as JPEG |
| PDF → JPG / PNG | pdf.js | canvas render, packed into a ZIP built in `core.js` |
| PDF → texto / Word | pdf.js | text layer extraction; `.docx` written as OOXML |
| JPG/PNG/WEBP → PDF | pdf-lib | WEBP flattened through a canvas first |
| Word → PDF | `DecompressionStream` + pdf-lib | unzip `.docx`, parse OOXML, lay out text |

`pdf-lib` and `pdf.js` are **self-hosted** under `/vendor/` and loaded lazily on
first file selection. No third-party request is made while a tool runs, which is
what makes the privacy claim verifiable in the Network tab.

Where the browser genuinely cannot do the job — OCR, PDF encryption, PDF to
Excel — the tool page says so instead of shipping a bad result. Those appear as
disabled "em breve" cards and are deliberately not indexable pages.

## SEO architecture

The domain is an exact match for the highest-volume query in the market, so `/`
is the merge tool itself rather than a landing page.

- **31 indexable URLs**: 17 tool pages, 8 guides, 2 indexes, 4 legal/about.
- **One page per keyword cluster.** Synonyms (`unir`, `mesclar`, `combinar`) get
  their own pages, but each answers a genuinely different question — Portugal vs
  Brazil usage, the Adobe/Microsoft terminology, mixing file formats — rather
  than repeating the merge page.
- **Structured data**: `WebSite` + `SearchAction`, `Organization`,
  `SoftwareApplication`, `HowTo`, `FAQPage`, `BreadcrumbList`, `Article`
  (196 entities across the site), emitted as one `@graph` per page.
- **Core Web Vitals**: no framework, no web fonts, no CDN. CSS is inlined
  (~17 KB), so a page renders in one round trip; the PDF engines are only
  fetched once a file is picked.
- `scripts/check.mjs` fails the build on a duplicate title or description, a
  missing canonical, more than one `<h1>`, a broken internal link, a missing
  asset or invalid JSON-LD.

## Deploying

The output is a plain folder — Cloudflare Pages, Netlify, Vercel or any static
host works. `netlify.toml` and `vercel.json` are included; `dist/_headers` and
`dist/_redirects` are generated by the build and carry the CSP, cache policy and
canonical redirects.

Set the analytics ID in `src/data/site.mjs` (`gaId`), or leave it empty to omit
the tag entirely.

## Regenerating images

`npm run images` re-renders the favicon, PWA icons and all 28 Open Graph cards
with Chromium. The output is committed, so a deploy never needs a browser.
